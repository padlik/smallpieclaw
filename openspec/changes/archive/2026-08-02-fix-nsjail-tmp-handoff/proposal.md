## Why

nsjail's `/tmp` inside the shell sandbox is a per-session scratch directory — ephemeral by design, backed by tmpfs-like behavior, and that's correct: it's meant to behave like a normal throwaway `/tmp`, created at startup and cleaned up at shutdown exactly as it always has.

Separately, `/tmp/{agent_name}` (`agent_name` = `app_cfg.agent.agent_name`, default `"piclaw"`) is already the agent's persisted temp/handoff directory *outside* the jail — a default trusted directory per `access_control.py`'s `TrustedZoneChecker`, and the location the prompt/tool docs (`builtin_tools/descriptors.py:110`) already tell the model to use for handing off large output between shell calls. But it was never mounted into the jail at all.

Today, `main.py`, `access_control.py`, and the config layer don't all agree on what this directory is — `access_control.py` honors an operator-settable `paths.tmp_dir` override, and `main.py`'s own computation is separately buggy and doesn't reliably land on `/tmp/{agent_name}` either. This proposal settles it: `tmp_dir` is `f"/tmp/{app_cfg.agent.agent_name}"`, set once at startup, full stop — how that's computed internally is an implementation detail (see `design.md`); what matters is there's exactly one value, used everywhere. The `paths.tmp_dir` config override is removed so there's nothing left to disagree with.

So when a sandboxed script writes a large result to `/tmp/{agent_name}/...` expecting the agent to read it back afterward via `file_read`, the write actually lands in the jail's ephemeral scratch `/tmp`, not the real host directory `file_read` looks at outside the jail. The subsequent `file_read` call finds nothing, and the agent retries until it exhausts its iteration budget, effectively getting stuck.

The fix is narrow: make `/tmp/{agent_name}` visible inside the jail too, at its real host path, alongside the existing ephemeral `/tmp` scratch mount. Nothing about the scratch mount itself — its ephemerality, its creation, or its cleanup — needs to change; it already works exactly as intended.

## What Changes

- **The `paths.tmp_dir` config override is removed entirely.** There is now exactly one way to determine the agent's temp/handoff directory anywhere in the codebase: `f"/tmp/{app_cfg.agent.agent_name}"`. `access_control.py`'s `TrustedZoneChecker` no longer has a `paths_config.tmp_dir`-based fallback branch — it always computes this same value. `main.py`'s own separate, buggy computation (cwd-basename-keyed, with a broken unset-fallback) is deleted and replaced by the same one-line expression. There is exactly one resolution, used everywhere: by the directory `main.py` creates at startup, by what `access_control.py` trusts, and by this new mount's source.
- **`/tmp/{agent_name}` — the agent's default trusted temp directory — is bind-mounted read-write inside the jail at its real host path**, immediately after the existing `/tmp` scratch mount so it isn't shadowed. Since this directory is already created at agent startup (before the shell tool is ever invoked) and there is no override to account for, no validation, blocklist check, or missing-directory handling is added for this mount: if the directory is somehow absent by the time a shell call runs, that means agent startup itself is broken, and the mount is `mandatory: true` — the shell call fails loudly rather than silently degrading, since a missing directory here indicates a real bug, not a configuration case to tolerate. A malformed `agent.agent_name` (e.g. containing path separators) is an existing configuration problem outside this change's scope, not something this mount adds handling for.
- **`TMPDIR`, `TMP`, and `TEMP` are injected inside the jail as base envars, set to `/tmp`** — the ephemeral scratch mount, matching what tools already default to — not to `/tmp/{agent_name}`. This is the simplest option: scripts that want their output to persist and be visible to the agent write to `/tmp/{agent_name}/...` explicitly, per the existing, already-documented convention; tools that call `mktemp`/`tempfile` without an explicit path keep landing in throwaway scratch space exactly as they do today.

Nothing else changes: the per-session scratch `/tmp` mount's creation, location, and shutdown cleanup are untouched.

**Rejected alternative**: bind-mounting host `/tmp` directly instead of `/tmp/{agent_name}`. Rejected because host `/tmp` holds live same-user IPC sockets (tmux control socket, X11 socket, a standalone ssh-agent socket) — mounting it read-write into the jail is a sandbox escape.

## Capabilities

### Modified Capabilities

- `nsjail-shell-sandboxing`:
  - **ADDED**: a requirement that `/tmp/{agent_name}` is bind-mounted read-write inside the jail at its real host path, `mandatory: true`, immediately after the existing `/tmp` scratch mount.
  - **MODIFIED**: "Environment variables are isolated with three-layer injection" — the always-injected base envar set grows from `PATH`/`HOME`/`LANG`/`TERM` to also include `TMPDIR`, `TMP`, `TEMP`, all set to `/tmp`.

## Impact

- **Code**: `config_schema.py` (`PathsConfig.tmp_dir` field and its parsing removed), `builtin_tools/access_control.py` (`TrustedZoneChecker`'s `paths_config.tmp_dir`-based fallback branch removed — always computes `f"/tmp/{agent_name}"`), `config.toml.example` and `README.md` (the `paths.tmp_dir` documentation removed), `main.py` (deletes its own cwd-basename `tmp_dir` computation; computes `tmp_dir = f"/tmp/{app_cfg.agent.agent_name}"` and passes it to `BuiltinExecutor`; also deletes the separate cwd-basename `agent_name` computation — `nsjail_state_dir`, `trusted_dirs.json`'s location, the conversation store, and vault migration paths now all key off `app_cfg.agent.agent_name` too, the same single config-sourced value used everywhere else), `nsjail_config.py` (`NsjailConfigBuilder.__init__` gains a `tmp_dir` parameter; `build()` emits the new `mandatory: true` mount immediately after the `/tmp` scratch mount, and the new base envars; `_load_trusted_mounts()` also skips `trusted_dirs.json` entries nested under `tmp_dir`, mirroring the existing `session_tmpdir` skip, to avoid a duplicate mount stanza), `builtin_executor.py` (threads `tmp_dir` through to the builder as an already-resolved value — never re-derives it from its own, unrelated `agent_name` parameter, mirroring how `nsjail_session_tmpdir` is already threaded; nsjail activation now also requires `tmp_dir` truthy, matching the existing `nsjail_session_tmpdir` gate), `tests/test_config_schema.py` and `tests/test_access_control.py` (update/remove tests that construct `PathsConfig` with a `tmp_dir` argument or assert on it).
- **Config**: removes the `paths.tmp_dir` config key entirely. No new config keys are added.
- **Behavior**: `tmp_dir` becomes reliably `/tmp/{agent_name}` everywhere it's consumed — `access_control.py`'s trust, `main.py`'s `os.makedirs`/`TMPDIR`/`TMP`/`TEMP` env vars, the model-visible prompt text, and the nsjail scratch directory's own on-disk location (it inherits `TMPDIR`, so it now lives under `/tmp/{agent_name}` instead of wherever it landed before). For an operator who had explicitly set `paths.tmp_dir` to a custom value, that value is no longer honored anywhere. No effect on the `file_read`/`file_write` tools themselves — they already assume `/tmp/{agent_name}` is the shared drop zone.
- **Security**: adds one RW mount at a fixed, already-trusted path with no new validation surface. Removing the `paths.tmp_dir` override also removes a possible source of divergence between what's trusted and what's mounted.
