# Provider model catalog — exploration brief

## Decision

Add `provider-model-catalog` as a new capability; the proposal's confirmed modified capability map is `per-model-context-window`, `provider-credential-inheritance`, `llm-error-recovery`, `agent-runtime-construction`, `native-tool-calling`, `xdg-path-resolution`, `telegram-command-surface`, and (amended) `scheduled-job-execution`. Sub-agent run admission consumes the new catalog contract but its existing ownership/context contract does not change; scheduled jobs gain the settled selector exception below; prompt assembly and secret resolution likewise need no deltas. Keep `[embeddings]` and graph-memory settings as explicit exceptions. Evidence: `providers/_utils.py:115`, `llm_client.py`, `prompt_builder.py:53`, `prompt_loader.py`, `main.py`, `agent_runtime.py`, `graph_memory.py:1497`, `backfill_graph_memory.py`, plus existing baseline specs cited below.

## Final contract and flow

- Human config has only `[providers.<provider-id>]` connection entries: `type` (`openai`, `openrouter`, `anthropic`, `google`, `ollama`), optional `api_key` (env/sec reference), `base_url`, and `request_timeout`. Provider connection ID is canonical; upstream model ID is exact and parsed at the first `/`. No operator per-model config or provider/per-model `max_tokens`, `temperature`, or `top_p`. Ollama is cloud-only: no local default and no `:cloud` suffix inference. Preserve unrelated embeddings/graph configuration.
- App-owned `models-config.toml` at `$XDG_CONFIG_HOME/<agent>/models-config.toml` stores generated per-provider catalog metadata/capabilities/context and output limits plus remembered main model ID. Startup and `/models` refresh catalogues; a successful provider refresh replaces only that provider's inventory, while failure preserves its last good inventory and marks it stale; stale discovered entries remain selectable. Never substitute for a saved ID: retain a missing saved ID, and if no ID is saved or the saved ID is absent, keep daemon/commands ready but gate model work until explicit `/models` selection. Every deliberate main-model selection is persisted, and write failure is reported as failure, not success. Offer a simple catalogue listing (roughly 20 models); handle Telegram callback-size limits without introducing general pagination. Selection is only from discovered entries. Prompt/tool consumers use the shared registry to report available/active models and capability known/unknown/stale state, never secrets; catalog presence does not guarantee account callability.
- Each admitted run resolves explicit job/sub-agent model selection, otherwise snapshots the active main model at admission; pin model, provider endpoint, and metadata for its lifetime. Remove startup-frozen `agent.background_model`. No automatic model fallback anywhere (vision, on-demand, plan, diagnostic, inference/provider/credential/capability/context errors), with ONE settled scheduled-selector exception (see "Scheduler exception"); no jobs converter is included. Ordinary requests omit temperature/top-p; optional output caps are omitted, required caps use reliable output metadata bounded by remaining context, and unknown required output limits fail actionably. If context-limit metadata is absent, use `agent.ctx_max_tokens` as a visible assumed local budget, not inferred provider capacity. Retry policy is `[agent] max_retries=4` additional attempts (5 total), `retry_delay=2.0s`, exponential delays 2/4/8/16; retry transient errors only, fail permanent errors immediately, and `max_retries=0` means initial attempt only. Remove provider/model retry knobs. Keep one automatic budget across native/JSON/human-wait/empty-output control-flow paths; retry a failed current request only before output or side effect (even after earlier completed tool turns), and never replay completed tools or a whole run automatically. Explicit checkpoint recovery is user-directed, not an automatic retry or implicit budget reset. A terminal error ends the run, not the bot.
- Remove vision auto-routing. `vision_query` requires an explicit verified vision model; unknown capability is shown and image requests fail safe. A manual smaller-model switch remains selected, but an oversized next request fails without truncating history/source; this does not remove normal compaction. Graph enabled requires explicit canonical `graph_memory.extraction_model` and valid explicit global `[embeddings]` model/provider; if either is missing/invalid, startup gives an actionable WARN and disables graph only—never infer from default/first model. Live backfill with invalid prerequisites fails before DB side effects; dry-run touches no DB/embedding/inference. See "Independent graph". Embeddings stay independent of chat model and chat credentials/endpoints; preserve explicit settings and matching provider inheritance, but no fallback to active-chat credentials. Preserve graph extraction's fixed `temperature=0.1` and `max_tokens=1024` as a named exception to ordinary generation parameters.
- Migration is previewable, backed up, recoverable and idempotent. Convert only unambiguous settings; preserve unresolved TOML references without resolving/exposing secrets; remove obsolete selectors/settings; report discarded per-model tuning, without promoting it to provider defaults or hidden overrides. Require operator choice for ambiguous account selectors. Seed saved default only from an unambiguous old actual default; do not reconstruct manual-switch history. Existing local Ollama setup requires explicit cloud replacement, never redirect silently. Malformed/unknown scheduled-job selectors are handled at execution per "Scheduler exception"; no converter. Do not rewrite jobs, logs, prompts, memories or vectors. Self-awareness/prompt and tool consumers use the same registry to show available models, active model, capabilities and unknown/stale state, never secrets; availability is not a promise of inference access.

## Baseline mapping / evidence

- `per-model-context-window`: **Per-model context window awareness**, **Vision routing via all-models scan**, **Fallback models deprecation** (replace scan with explicit selection/capability fail-safe; retain normal compaction).
- `provider-credential-inheritance`: **Provider-level model defaults**, **Provider-level embedding defaults** (replace model defaults; preserve embedding exception).
- `llm-error-recovery`: **LLM errors are classified into typed categories**, **LLM error handling configuration** (retry policy changes; user-directed checkpoint recovery remains distinct).
- `agent-runtime-construction`: **Runtime options preserve construction knobs** (per-call generation tuning removed; resolved model carried through runtime products).
- `native-tool-calling`: **Native tool calling path**, **LLMProvider protocol extension**, **Provider-native tool calling implementations** (shared parameter/retry policy; retain single-model request routing).
- `telegram-command-surface`: **Public Telegram command discovery excludes removed and hidden commands** (add `/models` discovery and callback-safe selection).
- `xdg-path-resolution`: **XDG Base Directory resolution** (add catalog path).
- `scheduled-job-execution`: no existing model requirement; add a requirement for execution-time selector resolution (existing "Scheduled runs have distinct complete execution records" and "Job execution history is bounded" retained unchanged).

`sub-agent-context` has no behavior delta: its ownership and context isolation remain; model admission/pinning is specified by the new catalog capability. `scheduled-job-execution` gains a delta only for the scheduler exception below (existing context/memory boundary, approval, record, history, and notice requirements are unchanged; baseline has no model requirement today). `structured-prompts` and `secure-secret-resolution` remain unchanged; catalog awareness is supplied from the new registry and provider API-key references use existing secret resolution. `provider-credential-inheritance` changes its model requirement and the embedding fallback scenario: embeddings remain explicitly configured and may use matching provider settings, but never the active chat model's credentials/endpoints.

## Scheduler exception (settled by user, amends earlier no-fallback/obsolete-selector-fails policy)

- Bot startup never depends on scheduler jobs; whatever is configured is processed at runtime and job/config errors are contained, never aborting startup. Fail-fast malformed-selector errors in scheduler loading/constructor were rejected.
- A missing or `None` saved job model is a silent inherit marker on add/load/execution (not malformed, no warning); modify omitted/`None` stays NO CHANGE (not a clear operation). Exact non-blank strings are preserved without trimming.
- At execution, a malformed (empty/whitespace-only string, or any non-`None` non-string value) or catalog-unresolvable (exact non-blank string with an absent entry) saved/job model selector warns and inherits the active Main model only if Main is itself valid; the raw selector is preserved, never normalized/dropped/stringified, and Main selection is unchanged. Stale discovered entries remain resolvable/selectable (staleness is not unknown). No catalog => no valid Main => normal job failure. No valid active Main: ANY scheduled job, even with a valid explicit canonical selector, fails normally before any model call; ordinary gate unchanged.
- Fallback applies only before admission (selector cannot resolve); a valid explicit selector hitting credentials/capability/context/inference/provider-outage errors never falls back, so no cross-model retry, no whole-run/model retry, no replay.
- Legacy per-job `fallback_models`: ignored with a runtime WARN at job execution (not a job-load/startup error), job config not rewritten, no cross-model retry. Explicit agent-level fallback settings in human config are still removed/rejected. Design follow-ups (deferred): raw empty/non-string retention, per-job int-cast containment, persistence/reload atomicity.
- Ordinary on-demand, plan, diagnostic selectors stay strict; every ordinary admission requires an active Main even for an explicit known canonical selector.
- Add omission/None inherits; modify omission/None leaves unchanged (no clear operation). Run-ID/active tracking and `last_run` history happen before spawn, terminal record after; no pre-spawn terminal row/trace invented. Jobs are not migrated or rewritten. Parsing/persistence/invalid-representation details are for design. Current implementation (C1 complete, C2 paused) has not implemented this; it is intended amended behavior.

## Independent graph (settled by user)

- Graph extraction and standalone live backfill resolve the explicitly configured canonical graph selector independent of Main selection, via proposed `resolve_graph_model(selector: str) -> RunModel` (not an existing API) that leaves Main selection/settings/revisions unchanged; ordinary admit keeps its active-Main check. One settled pin per graph component/backfill invocation; owned extraction clients via `for_graph_extraction` keep fixed `temperature=0.1`/`max_tokens=1024`. Independent explicit embeddings unchanged.
- Prerequisite budget follows actual `compute_request_budget`: unknown output limit is allowed even with the 1024 cap; unknown context/total uses the labelled local fallback; known output limit below 1024, malformed limits, and non-positive headroom fail. Invalid prerequisites: startup WARN disables graph only; live backfill fails before DB side effects; dry-run touches no DB/embedding/inference. Google resource names/supportedGenerationMethods are discovery-only (no capability inference, no managed-setting changes). Exact API/budget details are for design.

No material open questions. Rejected: human-maintained per-model lists/tuning; first-model/default inference; automatic fallback on inference/provider errors or any cross-model failover (the scheduled selector-resolution exception above is the sole pre-admission fallback); local Ollama/CLI suffix guessing; vision auto-routing; silent model/default substitution; migration of run history or jobs. Capability catalog listing is intentionally simple, not a generic pagination feature.
