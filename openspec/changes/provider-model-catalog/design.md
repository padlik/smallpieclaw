## Context

The frozen proposal replaces operator-maintained `[[models]]` with provider connections and an app-owned discovered catalog. The catalog must be one source for `/models`, prompt/tool model descriptions, main-model selection, and model admission; it must not become an LLM configuration container or a new executor. `main.py` remains the composition root and `AgentRuntime` remains the sub-agent construction boundary. `SubAgentSupervisor` retains lifecycle/scheduling ownership. Embeddings remain independently hard-configured.

Three settled boundaries shape the amended design: (1) the scheduler keeps raw job configuration and a bad scheduler file or job never blocks startup or other jobs; (2) ordinary admission is strict, with one scheduled-job selector fallback applied before the run model is pinned; (3) graph extraction pins its own model independently of the main selection and owns its extraction clients. APIs and flows named **PROPOSED** below (`ModelRegistry.admit_scheduled`, `ModelRegistry.resolve_graph_model`, the scheduler load result/document/encoder) do not exist yet; the implementation is in progress (C1 complete, C2 paused) and has not implemented the amended behavior. Pre-existing code is cited by file and line only where a decision depends on it.

## Goals / Non-Goals

**Goals:** One managed catalog and selection owner; safe refresh and atomic persistence; immutable admission-time model/connection/metadata snapshots; faithful provider limits and explicit unknown-state handling; separate chat, embeddings, and graph-extraction policy; recoverable configuration migration; scheduler configuration isolated from bot startup, with job errors contained to the job; one root-owned admission per run (no double admission or credential resolution); raw scheduled selectors preserved and classified only at execution; graph model pinning independent of the main selection.

**Non-Goals:** Reworking `main.py` as composition root, replacing `AgentRuntime`/`SubAgentSupervisor`, changing scheduled-run ownership or permissions, inventing aliases or model tuning, guaranteeing inference access from catalog presence, rewriting conversations/history/jobs (no job converter, and no new automatic job rewrite, delete, or import migration), building a generic pagination framework, making embeddings follow chat selection, a general-purpose TOML writer or new dependency, redesigning the scheduler state JSON, changing the public `PlanStep` shape, adding public tool/schema surface for scheduled admission, or any cross-model retry for a valid explicit selector.

## Decisions

### Component boundaries and data flow

```text
Operator -- /models --> Telegram commands/callbacks --> ModelRegistry
                                                      +--> ModelDiscovery --> provider catalog APIs
                                                      +--> ModelSettings --atomic--> models-config.toml
Prompt builder / alternate prompt loader / tool descriptions <-- registry view
Scheduled jobs (raw scheduler.toml document + derived runtime view)
   -- trusted internal spawn --> Root factory (main.py) --> Registry.admit_scheduled(raw selector) [PROPOSED] --+
Other ordinary runs (main turn / on-demand / plan / diagnostic)
   --> Root factory (main.py) --> Registry.admit(selector) -----------------------------------------------------+--> frozen RunModel pin
Graph component / live backfill --> Registry.resolve_graph_model(selector) [PROPOSED] ---------------------------+
frozen RunModel pin (run) --> main controller or AgentRuntime.create (RuntimeOptions.run_model, no re-admit)
                                   +--> run-local LLMClient --> one provider
Explicit [embeddings] --> EmbeddingClient --> embedding provider --> index/memory
frozen RunModel pin (graph) --> extractor closure --> per-extraction owned LLMClient.for_graph_extraction
                                   (closed in finally) --> one provider --> graph writer / backfill
```

`model_registry.py` owns immutable `ModelRecord` values and the catalog state machine: view, select, admit, refresh/merge. It owns one state/write lock. `model_discovery.py` fetches and normalizes complete provider inventories and optional exact-match supplement metadata, using existing `httpx`; it does not own cached state. `model_settings.py` narrowly loads, validates, and atomically replaces the generated TOML; it does not resolve credentials or apply selection policy. `main.py` constructs these once and wires them. `AgentRuntime` receives admission-resolved model data while preserving its existing profile/product boundary. `llm_client.py` receives one immutable run snapshot and owns neither the inventory nor a mutable active-model index; `interfaces.py` carries the run-local provider contract without inventory ownership. Its `chat_with_fallback`-named compatibility wrappers may not introduce model routing or a separate retry budget. The model-tuning fields `max_tokens`, `temperature`, and `top_p` are removed from `builtin_tools/schemas.py` and `builtin_tools/descriptors.py` spawn schemas, builtin argument parsing/validation, `main.py` sub-agent factory signatures, and `RuntimeOptions`/`AgentRuntime` forwarding. If obsolete fields are supplied, return an actionable tool-validation error before model admission or any LLM call; never silently ignore them or create hidden tuning. Preserve other runtime options (model, context, label, iteration limit, trace, profile, supervision, callbacks).

`RunModel` freezes the selected `ModelRecord`, resolved immutable provider connection, selection/admission revision, and model metadata. Secret-bearing values are excluded from persistence and `repr`; frozen objects contain no mutable dict/list aliases. The provider credential is resolved for the run, passed only to the matching provider client, and never included in prompts, UI, errors, or managed settings. A run pins endpoint, model, and metadata; refresh or a later main selection cannot mutate it.

Diagram notes (lightweight C4-style container/component flow; no formal four-level C4 set). The root factory in `main.py` is the only caller of `admit`/`admit_scheduled`: it branches on the existing `runtime_profile`, so scheduled construction calls `admit_scheduled`, every other ordinary profile calls the unchanged `admit`, and each produces exactly one `RunModel` per run. `AgentRuntime.create` receives that pin through `RuntimeOptions.run_model` and never re-admits (it already rejects a non-`RunModel` at `agent_runtime.py:327`). Ordinary `Runtime.create` ownership, native tool wiring, R6 guards, and permission ownership are unchanged, and `LLMClient` instances sit strictly below the pins. Graph resolution is a third, separate entry: it never passes through ordinary admission and never changes main selection, settings, or revisions. The `RunModel` shape is unchanged; the registry-internal checks used by `admit_scheduled` (Main selection identity, document object identity) are not RunModel fields.

### Identity, inventory, and managed settings

The canonical model ID is `<provider-connection-id>/<exact-upstream-id>`; split only at the first slash. Connection ID chooses the adapter/account/endpoint; upstream ID is the exact ID sent to inference. Display names are not selectors. Do not infer aliases, add/remove suffixes, or use resource names in place of inference IDs.

Provider discovery uses complete pagination where supported and only reliable provider metadata:

| Adapter | Inventory and metadata contract |
|---|---|
| OpenAI | Inventory IDs only; no reliable context/output/capability inference from that inventory. |
| Anthropic | Follow every cursor page; retain nullable `max_input_tokens`, `max_tokens`, and `capabilities.image_input.supported`. |
| Google | Follow every page; retain `inputTokenLimit`, `outputTokenLimit`, `supportedGenerationMethods`, and inference `baseModelId` separately from resource name. |
| OpenRouter | Retain catalog context and modality data; output limits remain unknown when absent. |
| Ollama | Cloud tags/IDs only; metadata may be sparse. Default the cloud connection origin to `https://ollama.com`, require authentication, and join discovery at `/api/tags` without duplicating `/api`. The SDK/native inference path uses the same origin with its adapter-correct path. Reject explicit localhost base URLs. Do not use suffix guessing or `/show` assumptions. |

Supplement from a fetched public `models.dev` catalog only; send no account, endpoint, credential, or per-model/request data. Match adapter and upstream ID locally and exactly. Provider data wins field-by-field; supplement only unknown fields and label every field's source. A supplement cannot create inventory entries and does not use fuzzy aliases or inferred dates; supplement failure does not invalidate provider inventory. Capability booleans are tri-state: `true`, `false`, absent/unknown. A provider's explicit `false` is never overwritten. Discovery and inference use the same configured connection/endpoint/auth policy; existing hard-coded Anthropic/Google inference endpoints must be moved behind that connection boundary.

Version 1 managed file shape (no raw API responses, credentials, secret references, base URLs, or error bodies):

All token limits must be positive integers (booleans are not integers for validation). `models.sources` records the source per metadata field. Optional catalog-level sanitized error codes cannot expose endpoint, account, body, credential, or `env:`/`sec:` reference. A missing or corrupt managed file leaves commands available with no active model; preserve corrupt input before any repair/overwrite.

`XDGPaths` exposes a pure `models_config_file` path under the resolved agent `config_home`, including custom `XDG_CONFIG_HOME`; callers do not reconstruct paths locally. The managed file remains in the XDG private home, inaccessible to file tools and the jail under ADR-0028. Catalog presentation is through authorized application surfaces only.

### Refresh, persistence, and selection state machine

Persisted remembered ID and runtime active selection are distinct. Startup restores active selection only if the remembered ID is in the validated current catalog; otherwise preserve the ID but stay inactive. No ordinary model admission (`admit` and `admit_scheduled`)—including an explicit job/sub-agent override—is allowed until `/models` makes a valid main selection active. The one carve-out is the separate, explicit graph resolver `resolve_graph_model` (see "Independent graph resolution"), which never requires Main and does not change this gate for any ordinary path. Every selection must resolve to a discovered entry and persist successfully before it becomes active. On write failure, keep the prior active selection and report failure.

Refresh fetches outside the registry lock against a captured connection fingerprint and refresh generation. Discard results if the connection changed/deleted or a newer refresh generation completed. Validate all pages before merge: a complete successful response replaces that provider's inventory, including a valid empty inventory; incomplete, malformed, or failed responses preserve last-good entries and mark them stale. A deleted connection purges its entries despite cache. Supplement lookup failure leaves good provider inventory intact. Merge with the latest main selection under the shared lock; atomically persist the candidate before publishing it as durable. A refresh persistence failure is reported as non-durable; runtime admission must still reject a removed/changed connection safely.

If a successful refresh removes the active/saved model, retain the remembered ID, invalidate active selection for future admissions, and leave running `RunModel` snapshots untouched. Rediscovery in the same process does not reactivate it; explicit selection is required. Stale entries from a failed refresh remain discoverable/selectable and are visibly labelled stale. Status labels distinguish **selection** (`active`, `no selection`, `saved selection unavailable`), **inventory** (`fresh`, `stale`; discovery is not account callability), **capability** (`known`, `unsupported`, `unknown`), and **budget** (`provider metadata`, `assumed local context`, `assumed local completion reserve`).

`/models` shows a simple list sized for roughly 20 entries. Callback data uses short opaque tokens (at most 64 bytes), never model names/aliases. Expired tokens ask the user to reopen `/models`; callbacks revalidate current inventory before selection. Prompt builders use a shared registry view that presents the pinned current run model separately when it differs from or has disappeared from current inventory. This bounds Telegram payloads without a general pagination system.

### Scheduler isolation, raw job document, and persistence

Current behavior this replaces (verified in `scheduler.py`): `_read_config_jobs` (1591–1670) returns the same empty map for a missing, unreadable, unparseable, and valid-empty file; it casts `int(job_cfg.get("context_max_messages", 50))` unguarded (1648), turns any falsy `model` into "absent" with `job_cfg.get("model") or None` (1646), and writes migrated legacy schedules back on load (1496–1498, 1677–1679). `_serialize_job` (1521–1561) rebuilds each job from runtime metadata, drops unknown fields, and omits a falsy `model` (1544). `_save_scheduler_toml_locked` swallows `OSError` after a warning (1588). `_save_state_locked` (1373–1397) dumps `**meta` into the state JSON. `_load_dynamic_jobs` (1435–1454) imports legacy JSON into the TOML and deletes the JSON. `__init__` casts scheduler-local settings with `int(...)` (440–449). The proposed behavior below applies only to the scheduler; no other subsystem's configuration contract changes.

**Isolation.** Scheduler construction, load, start, and registration never raise into `main.py` or block startup. This includes malformed whole-file TOML, numeric casts (including scheduler-local settings), job shapes, state/storage failures, and registration failures. Whole-scheduler failures are contained to the scheduler; per-job failures are contained to that job; both are logged and operator-visible, while commands, Telegram, and model work remain ready.

**Explicit load result (PROPOSED).** A scheduler-local `SchedulerLoadResult` distinguishes `valid` (a parsed file, including one with zero jobs), `missing`, `unreadable`, and `unparseable`. It carries the parsed raw document when available, the path, a hash of the exact bytes parsed, and an actionable operator notice (file path/location, what failed, what to do; no file content). The notice is sent once at startup through the existing notify path and stays visible in job list/show responses.

| Situation | Behavior |
|---|---|
| Cold start, file `unreadable` or `unparseable` | No executable job map; visible file error; the file bytes are preserved and no write may overwrite them (mutations return the error until the file parses). |
| Cold start, file `missing` | No jobs; the first mutation may create the file. |
| Reload fails (`unreadable`/`unparseable`/staging error, or the file changed between parse and publish) | The last-good map, raw document, hash, and registrations are kept untouched; the failure is reported to the caller with an actionable "reload again" instruction; no automatic retry. |
| Reload succeeds | A complete proposed map and its registrations are prepared first (outside the locks), then, after a recheck that the file still equals the bytes the reload parsed, published under `_running_lock` then `_save_lock` together with that hash; an operator edit made before the reload is loaded, and a concurrent mutation is never stomped. No empty or half-built map or registration set is observable. |
| Legacy `scheduled_jobs.json` unreadable or unparseable (cold start or reload) | A contained operator notice; TOML jobs continue unaffected. On reload the last-good legacy jobs are kept. |
| Reload required after a post-commit publication failure (`RELOAD_REQUIRED` latch) | Mutations are refused before `_on_attempt` with an actionable message until a reload succeeds. |
| Legacy job partially bad | That job is contained (`config_error`/launch failure like any bad job); no other legacy job is dropped. |
| Parseable job with a bad time/scheduling field (schedule type, cron/run_at, legacy fields that cannot derive a cron, `enabled` not a bool) | Raw fields retained, `config_error` visible in list/show, the job is visibly **unscheduled** and never fires; `run_now` returns the existing failure result with that error. |
| Parseable job with any other bad field (non-string `task`, wrong-typed `notify`/`preserve_context`/`context_max_messages`/`max_iterations`, invalid `overlap_policy`) | The job stays scheduled; at fire time it produces a normal recorded launch failure (see lifecycle). A non-string `task` is never treated as an empty-task reminder; only a blank string is a reminder. |
| One bad job | Healthy sibling jobs load, register, and run normally. |

Field checks are type-strict classification of the raw value (no `int()`/`bool()` coercion that can raise or silently convert). `model` is never classified at load: no load-time warning or `config_error` for any `model` value. A legacy per-job `fallback_models` is ignored with a runtime WARN when that job executes, never as a load or startup error, replacing today's load-time drop-and-warn (1651–1657); it never enables cross-model retry and stays in the document.

**Raw document and derived view.** The parsed raw document is the authoritative persisted job configuration; `_jobs_meta` becomes a derived runtime view overlaid with run state (`last_run`, `last_error`) and is never used to rebuild TOML. Legacy `daily`/`interval` schedules still derive a cron in memory, but a load never rewrites the file (the write-backs at 1496–1498 and 1677–1679 are removed), and no new automatic legacy job rewrite, delete, or import migration is added.

**Legacy `scheduled_jobs.json` (user-approved read-only compatibility constraint).** Legacy jobs stay runnable and are read non-destructively into the runtime view only; the destructive import-and-delete (1435–1454) is removed, and the legacy file is never deleted, overwritten, renamed, or automatically adopted into the TOML. When a tag appears in both sources, the TOML job wins. A JSON-only job carries source-tag metadata marking it legacy read-only; list/show display a plain-text `legacy, read-only` marker for it, and its refusal messages carry the legacy file path and manual-edit/reload instructions (text requirement only; no UI design). There is no edit/migrate mechanism, no persisted tombstone, and no adoption path. Mutation semantics follow:

- `modify_job`, `remove_job`, pause, and resume of a JSON-only job are refused before `_on_attempt` (disposition `refused`) with an actionable message: the legacy file path and manual-editing plus reload instructions (never raw secret data or file content). `run_now` of a legacy job uses normal admission.
- `remove_job` never reports false success for a JSON-only job. Removing a TOML job whose tag still exists in the legacy file would expose the legacy job on the next restart, so it is refused with the same path/manual-cleanup instructions until the shadowing tag is removed from the legacy file. The shadow check never relies on the cached map: the `remove_job` preflight reads the current legacy JSON from disk. A missing legacy file allows a normal remove; an unreadable or malformed legacy file refuses the removal before `_on_attempt` with an actionable message (resurrection cannot be ruled out); a present shadowing tag refuses it, even if the operator added that tag after the last reload and has not reloaded. Under the commit locks the legacy fingerprint read by the preflight is compared again; a change between preflight and commit fails the removal as an `executed` failure with no change. The locks do not control operator edits made afterwards: such an edit is new input to the next reload. No legacy overwrite, deletion, adoption, or tombstone is introduced. Normal modify, pause, and resume of a TOML job that shadows a legacy tag proceed (the TOML still wins).
- An operator who edits or deletes the legacy file and reloads sees the change; a failed reload follows the last-good rules above.

**Mutation persistence.** `add_job`, `modify_job`, `remove_job`, and pause/resume apply an explicit patch of only the requested fields to a deep copy of the parsed raw document (a value-level edit of the parsed structure, not a lexical text patch). TOML has no null, so an absent or `None` `model` on add is represented by omitting the key; `modify_job` with an absent or `None` `model` changes nothing (no clear operation). Public add/modify never check catalog availability: any TOML-representable raw selector (including `""`, whitespace, and non-strings) is stored unchanged. A value the encoder cannot represent (an arbitrary object, `None` inside a container, a non-string table key) fails validation before the `_on_attempt` hook, with no change. Validation refusals therefore precede `_on_attempt` (disposition `refused`). So does a preflight that finds the scheduler file already known unparseable or unreadable (cold state, or the failed-load state), the `RELOAD_REQUIRED` latch, or an unresolvable legacy shadow check: the mutation is refused with the file error and nothing is mutated. A failure that can only be discovered after `_on_attempt` — an external-edit hash mismatch, a candidate roundtrip failure, or a write failure — is `executed` with a failure result under the existing R6 semantics and is never reclassified as refused retroactively. R6 `_on_attempt` semantics are otherwise unchanged.

**Encoder.** A narrow scheduler-local recursive encoder of the whole parsed document (not a bounded lexical patch of known job keys) covers exactly what `tomli` can return: strings (escaping control characters, quotes, and backslashes), booleans, integers, floats including `inf` and `nan`, datetimes/dates/times, arrays, inline tables, and quoted keys. It adds no dependency and is not a general serializer. Untouched parsed values (including malformed selectors and legacy fields) are re-emitted as parsed. The only preservation guarantee is parsed-value equality (NaN-aware and type-strict); bytes, comments, and layout are not preserved and nothing promises otherwise (the existing rewrite already regenerates the file). A load never rewrites.

**Write protocol (shared locking and publication rules; the freshness check differs by operation).** The lock order is `_history_lock → _running_lock → _save_lock`; a mutation or reload publication takes `_running_lock` then `_save_lock` (taking `_history_lock` first only where the existing call already requires it), and holds both across the file write (mutations only) and the publication. No read, save, reload, history, or state-save path may acquire these locks in the opposite order, nor take another of the three while holding `_save_lock`; this is audited and proven by a concurrency test with no deadlock. A candidate is always prepared outside the locks and rechecked under them before anything is published.

*Mutation (`add_job`, `modify_job`, `remove_job`, pause/resume).*

1. **Prepare (before commit).** Build the candidate by patching a deep copy of the parsed raw document; encode it; parse the text back with `tomli` and compare with the candidate using a NaN-aware, type-strict equality (a boolean is not an integer; NaN equals NaN), which proves untouched values unchanged; and build the schedule triggers and registrations for the affected jobs without publishing them. A registration that cannot be prepared fails contained here, before anything is written, so no job is partially on disk. Preparation failure returns an actionable failure with all state intact.
2. **Lock and revalidate.** Acquire the locks, then revalidate the inputs the candidate was prepared from (the current raw document/generation); if they changed, discard the candidate and re-prepare from current state — never write a stale candidate. Re-read the file and require its hash to equal the **stored hash** (the hash of the last bytes this scheduler parsed or wrote), or, for a file recorded as missing, that it is still missing (a missing-file sentinel), and require it still readable and parseable. An external edit or unreadable/unparseable file is an explicit failure with prior state intact and no overwrite.
3. **Atomic write.** Retain the existing backup-and-prune behavior, write a temp file in the same directory, and `os.replace`; any `OSError` is an explicit failure instead of a logged warning.
4. **Publish as one unit.** Still under both locks, publish the raw document, the matching new file hash (the sentinel becomes the real hash after a first successful create), the runtime view, and the prepared registrations together, so a second mutation never mistakes the scheduler's own write for an external edit. Registrations were prepared and validated in step 1, so publication is not a configuration failure.

*Reload (and its publication).*

1. **Parse outside the locks.** Read the file bytes once, hash them (the **candidate input hash**), parse them, and read the legacy JSON the same way (with its own fingerprint); prepare the complete proposed map, view, and registrations.
2. **Lock and recheck.** Under the locks, re-read the file and require its hash to equal the candidate input hash — not the previously stored hash, so a legitimate operator edit (stored hash is old by definition) is accepted and loaded, while a mutation that committed between the parse and the publish (disk now differs from the candidate input) is detected and can never be overwritten. The legacy fingerprint is rechecked the same way. On a mismatch the reload fails with an actionable "the scheduler file changed while reloading; reload again" result, the last-good map, document, hash, and registrations are kept untouched, and nothing is retried automatically (no bounded re-prepare loop, and no model or run retry). On a match, publish the document, the candidate input hash as the stored hash, the view, and the registrations together, and clear any reload-required latch (below).

*Failure classification.* A failure before `os.replace` leaves disk and memory in the old state. After `os.replace` has committed bytes, the written file is authoritative and the old state is neither restored nor claimed preserved. Publication must install document, matching hash, and view as one unit. If the unit cannot be completed (including an irrecoverable exception, not a new framework), the scheduler never publishes the new hash alone while keeping the old document — that would let the next mutation silently revert the committed file. It instead sets a plain in-memory `RELOAD_REQUIRED` latch (a state flag, with no change to the state JSON format) and refuses every further mutation, before `_on_attempt` with disposition `refused` and an actionable "reload required" message, until a reload succeeds and clears it. The mutation that hit the failure is reported once as an `executed` failure under the existing R6 semantics, never reclassified as refused, and its message states that the file may already contain the change. Holding both locks across one small-file write is preferred to a window where disk and memory diverge. The hash is refreshed by every successful save and every successful reload publication. Edits an operator makes after a commit are simply new config input to the next reload; the locks do not claim to control the filesystem afterwards.

**State JSON.** The `scheduler_state.json` format is unchanged. Its `jobs` section is written from a projection of runtime/history-safe fields (scalar schedule/enable fields, `last_run`, `last_error`, `schedule_description`); the raw TOML selector and other raw unvalidated values are never copied into it, and no `default=str` is used to mask non-JSON values. Serialization errors are contained as a state-storage failure.

### Scheduled selector classification and root-owned admission

Saved-selector matrix (Main means the active main model; "valid Main" means an active selection that exists in the catalog):

| Raw job `model` | Add/load | Modify | Execution via `admit_scheduled` with valid Main |
|---|---|---|---|
| Absent or `None` | Inherit, silent | No change (no clear operation) | Main, no warning |
| `""` or whitespace-only string | Stored raw, no warning | Stored raw when requested | Malformed: WARN, Main |
| Any non-`None` non-string (bool, int, float, datetime, array, table) | Stored raw if TOML-representable | Same | Malformed: WARN, Main |
| Exact non-blank string present in the catalog, fresh or stale | Stored unchanged (no trim) | Same | Explicit: that model is pinned; staleness is not unknown |
| Exact non-blank string absent from the catalog (including case or padding variants) | Stored unchanged | Same | Unknown: WARN, Main |
| Any form, no valid Main (no catalog, no selection, saved selection unavailable) | Same | Same | Normal job failure before any model call, even for a valid explicit canonical selector |

Rules for every row: raw values are never trimmed, normalized, stringified, dropped, or rewritten, and the Main selection never changes. The fallback applies only here, before the model is pinned. A valid explicit selector that later hits a credential, capability, context, inference, or provider error fails the job with no fallback and no cross-model retry. Ordinary on-demand, plan, and diagnostic selectors stay strict, and every ordinary admission requires an active Main even for an explicit known canonical selector. Classification does not change how a stored value is stored. Everywhere a selector is shown, logged, or recorded before the pin exists — list/show, the pre-admission WARN, and execution records and notices — one bounded, redacted representation is used: `inherit` for absent, a classification label for `""`, whitespace-only, and non-strings (never the contents of a non-string), and a non-blank string bounded in length and passed through the existing secret redaction. The authoritative raw value stays retained unchanged in the document.

**`ModelRegistry.admit_scheduled(raw_selector: object) -> RunModel` (PROPOSED).** It does not call `admit`, and `admit` is unchanged. One operation resolves credentials and pins exactly once. Private helpers may be shared with `admit`.

1. Under the registry lock, require an active Main in the catalog (else the existing `no_active_selection` error, raised before any selector handling).
2. Classify `raw_selector` per the matrix: `None` inherits; a blank or non-string value is malformed; an exact non-blank string is looked up in the catalog verbatim. Choose the effective model (explicit entry, or Main for inherit/malformed/unknown).
3. Capture the model record, its provider connection fingerprint and configuration generation, the Main selection identity and selection revision, and the current document object (identity, not revision: a refresh whose persistence fails can remove an entry and publish a same-revision document, `model_registry.py` 513–517).
4. Emit the WARN for malformed/unknown (kind label; for an exact non-blank string, a bounded value through the log redactor; never the content of a non-string value) before credential resolution.
5. Resolve credentials outside the lock.
6. Re-acquire the lock and recheck the existing provider fingerprint, configuration generation, and model record, plus the Main selection identity/revision and document object identity. Any mismatch is a typed race failure (existing `connection_changed`; a new safe code, working name `selection_changed`, for the Main/document checks) with no re-lookup, no reclassification, and no retry.
7. Return the immutable `RunModel`.

A catalog refresh landing inside the credential window therefore fails that one run attempt visibly; the next fire reclassifies against the new state.

**Trusted scheduled spawn path.** The scheduler calls `builtin_executor.spawn_agent(spawn_args, options=SupervisionOptions(..., source=SOURCE_SCHEDULED))` (`scheduler.py:1219–1241`). Only the strict model-**shape** guard in `_validate_spawn_args` (`builtin_tools/agents.py:175–185`, which requires a non-blank string) is exempted, and only when `options.source` is the scheduled source. `options` is built by scheduler code and never from model-facing arguments; the model-facing `spawn_agent` path gets default options, so its strict shape guard, obsolete-argument rejection, and `model` validation are unchanged. All other checks are retained (task, depth, capacity, obsolete-argument rejection, context key, refusal paths, R6). The scheduler sets `spawn_args["model"]` whenever the job's raw `model` key is present and not `None` (replacing the truthiness test at `scheduler.py:1209`) and passes it as the raw object through the existing `model` factory keyword; only the internal annotation of `main.py`'s `sub_agent_factory(model=...)` widens. `ExecutionOwnership` and the `SCHEDULED_AGENT` profile already derive from `options.source` (`builtin_tools/agents.py:276–325`); no new public argument, schema, factory parameter, or supervision channel is added.

**Root branching.** `main.py`'s `sub_agent_factory` branches on the existing `runtime_profile`: `SCHEDULED_AGENT` calls `registry.admit_scheduled(model)`; every other profile calls the unchanged `registry.admit(model)`. The resulting `RunModel` is passed as `RuntimeOptions.run_model`; `AgentRuntime.create` never re-admits. The scheduler and builtin adapters pass the raw selector through and never call the registry. Execution records and notices store the pinned canonical ID after admission; before admission they store the bounded redacted representation above (never a raw unbounded string, a secret-bearing value, or a stringified non-string). Public `PlanStep` is unchanged: explicit-profile tests select a profile through the existing factory only, and the C3 fixture migration happens later.

**Scheduled lifecycle ordering.**

1. `_run_job` makes the overlap decision under `_running_lock` (`scheduler.py:1027–1045`).
2. If admitted as an agentic run, it mints the run ID and records active tracking in the same critical section. A blank-string task takes the empty-task reminder path with no run ID.
3. `last_run` is persisted (`scheduler.py:1235–1238`).
4. Scheduled spawn and admission run (supervisor → root factory → `admit_scheduled` → `AgentRuntime.create`).
5. The terminal record follows: success through the existing result recorder and `finish_cb`, or `_fail_launch` (`scheduler.py:1287–1315`), which records `last_error`, writes the failed execution record, alerts regardless of `notify=False`, and releases tracking in `finally`.

**Invalid `overlap_policy` / job-config failure.** An invalid `overlap_policy` (or other job-config failure at fire time) means the scheduler cannot interpret whether skip or restart was intended. It applies the conservative skip while the job is already active — it never cancels the active run and never infers an execution from the invalid value. When the job is not active it mints the owned run ID and active tracking, persists `last_run`, and then reports the config error through `_fail_launch` (a normal failed record, alert regardless of `notify=False`, tracking released in `finally`). A valid policy keeps the existing ordering. No pre-spawn terminal row is invented; callback, cancellation, ownership, and context-isolation behavior are unchanged.

### Run admission, wire limits, and model switching

At main-turn, on-demand, plan, or diagnostic admission, `admit` resolves any explicit selector exactly against the active registry (no trimming, aliasing, or fallback); otherwise it snapshots the active main selection. Scheduled admission uses `admit_scheduled`, which differs only in classifying the raw job selector before the pin (above). Every admission fails closed if no main selection is active, including a scheduled run with a valid explicit selector. Pass the resulting `RunModel` to the main controller or existing runtime factory; scheduled ownership, context isolation, callbacks, and result recording remain unchanged. For scheduled work, run-ID tracking precedes admission (see lifecycle), so an admission failure becomes the existing recorded launch failure and alert. On-demand spawn reports an actionable tool error; a plan-step records the normal failed step. Remove startup-frozen `agent.background_model`. There is no job converter. The only model fallback anywhere is `admit_scheduled`'s pre-pin selector classification; no path retries another model after a pin. Each LLM client is single-model for its full run.

Before sending, budget the actual target wire payload: system prompt, messages, tool definitions, native-call arguments/framing, and image estimates. The current estimator's omission of native-call arguments must be corrected. A documented combined window `C` limits prompt input plus completion reserve; separate provider input ceiling `T` and output ceiling `O` remain distinct, and `T` is never reduced by output reserve. Do not invent a combined `C` from `T` and `O` unless provider documentation explicitly defines that combined semantics. With no combined metadata, use `agent.ctx_max_tokens` as visibly assumed local `C` only when neither `C` nor `T` is known; never represent it as provider capacity. A provider may reject requests that exceed actual unknown limits; surface that error without rerouting. Retain the existing 85% compaction trigger and 256-token floor as heuristics; neither overrides an exhausted hard budget.

Reserve output and compute the hard input budget as follows:

| Documented input/context metadata | Optional output cap: wire behavior and reserve | Required output cap: wire behavior | Hard input budget |
|---|---|---|---|
| Combined `C` only | Omit cap. If known positive `O`, reserve its full value against `C`; if `O` unknown, reserve 1024 as assumed local accounting only. | Require known positive `O`; send `min(O, C-I)` when positive, otherwise fail. | `C - reserve`. |
| Separate input `T` only; no documented combined `C` | Omit cap. `O` does not reduce `T`; do not apply `agent.ctx_max_tokens`. | Require known positive `O`; send `O` because there is no documented combined window from which to compute a smaller cap. | `T`. |
| Both combined `C` and separate input `T` | Omit cap. If known positive `O`, reserve its full value against `C`; if `O` unknown, reserve 1024 as assumed local accounting only. | Require known positive `O`; send `min(O, C-I)` when positive, otherwise fail. | `min(C - reserve, T)`. |
| Neither known | Use assumed local `C = agent.ctx_max_tokens`; same optional-cap reserve as combined `C` only. | Require known positive `O`; send `min(O, C-I)` when positive, otherwise fail. | `C - reserve`. |
| Graph extraction (overlays the applicable row above) | Fixed internal cap/reserve 1024; never lower it. | Fixed internal cap 1024; this is policy, not discovered `O`. | Use applicable combined/local and separate-input constraints; fail an oversized extraction request. |

Here `I` is the estimated complete prompt/input payload. For known `C`, required output cap is bounded by positive `C-I`; with only `T`, it is bounded only by known `O`. For combined budgeting, a known optional `O >= C` leaves no positive hard input budget and MUST reject locally rather than silently reducing the reserve. A separate-input-only `T` remains the hard limit even when `agent.ctx_max_tokens` is lower. After selecting a cap/reserve, require a positive hard input budget and verify actual `I` does not exceed it or `T`. If the budget is non-positive or required `O` unknown, fail before network I/O. Example: Gemini `T=1,000,000`, `O=65,536`, no documented `C`, and `agent.ctx_max_tokens=90,000` has hard input budget `1,000,000`, not `90,000-65,536=24,464`. Estimate the complete target wire form, including tool definitions and native-call args; cache estimates only by exact assembled payload, target model/tokenizer, and definition revision, and recompute when any changes. For positive hard-input budget `B`, the existing compaction trigger remains `max(int(B * 0.85), 256)`; it is only a heuristic, and neither the 256 floor nor compaction can authorize a payload larger than `B`. Ordinary chat/native/JSON requests omit `temperature` and `top_p`. Graph extraction uses its fixed internal `temperature=0.1` policy and `max_tokens=1024` cap; existing adapter compatibility may strip unsupported sampling fields for specific models (for example, OpenAI reasoning models). The catalog does not add a temperature capability field, and stripping sampling is not a reason to choose another model.

The table is implemented by `model_request_budget.compute_request_budget(metadata, *, input_tokens, local_context_tokens, output_cap_required=False, fixed_output_cap=None)`; the graph row passes `fixed_output_cap=1024`. Its verified semantics are authoritative and are preserved, not redefined: each metadata limit goes through `_positive_optional`, which accepts only `None` or an exact positive `int` (a boolean, string, zero, or negative value raises `invalid_limit`); with `fixed_output_cap` a known `O` below the cap raises `output_limit_too_small` while an unknown `O` is allowed, and the cap is also the completion reserve; the labelled assumed local combined budget applies only when neither `C` nor `T` is known; otherwise the hard input budget is the minimum of the available candidates `C - reserve` and `T`, and a non-positive result raises `no_input_budget`. No new "required unknown `O`" exception is added for ordinary requests; the existing budget machinery, labels, and error codes are reused.

After a manual switch to a smaller model, install a conversation-revision guard. Minimal per-controller runtime state records the selection revision associated with the current conversation and the pending guard revision; restored history under a different selection is guarded without migrating the history. For the first request under that selection, assemble and estimate the complete candidate read-only before history mutation, summarization, or compactor invocation, using the same `C`/`T`/`O` budget cases above. If oversized, reject while preserving selected model, history, and source; do not auto-truncate or change the selection. The guard remains until reset or a manual change to a larger model. If it fits, proceed normally and clear the guard after success. Ordinary compaction remains available for other requests; recheck the complete outgoing payload before transmission. Do not blanket-disable or rewrite the existing compactor. When conversation history contains native tool-wire turns from an earlier provider, use the existing 1:1 linearization for incompatible request paths; never re-execute the recorded tool effects.

All image-bearing requests—including direct image messages and `vision_query`—use only the current run's pinned model and client. A verified `vision=true` sends the image through that client; `vision=false` or unknown capability rejects locally with an actionable instruction to select a verified vision model via `/models` or launch a new task with its canonical ID. `vision_query` takes no model override. Rejection does not alter the current run, main preference, or endpoint; image estimates are included in budget checks and no provider call is made on rejection.

For cloud Ollama, default the connection origin to the official `https://ollama.com` and require its API key. Route discovery to `/api/tags` and inference through that same official origin using the SDK's adapter-correct host/path convention. Normalize/join the API path exactly once; never construct `/api/api/...`. Reject localhost, LAN, self-hosted, or any other non-official origin; never forward the credential to another host. No suffix inference changes the selected host.

### Request retry and independent consumers

Use one `CallAttemptState` per current logical model request. A logical request starts when one model response is needed for the current ReAct step and ends only when a usable response/action is accepted, terminal failure is finalized, or cancellation occurs. Empty-response re-requests, native/JSON control-flow re-requests, safe parse-validation re-prompts, and human/confirmation waits before acceptance retain the same state; mode changes and loops never create/reset state. A successful accepted action ends that request; the next independent model call gets a new state while retaining prior tool results in history. A separate operator-initiated task is a new task, not a hidden retry loop. The state tracks mode, outbound attempts, and automatic retry budget. While a classified retry/recovery card is waiting for the operator, the logical request remains pending; its state is checkpointed and restored unchanged by explicit Retry/`/resume`, so recovery does not implicitly reset the automatic budget. The existing operator retry card and classification options remain; `unknown` remains operator-retryable. Each outbound call counts as one attempt. A user-directed retry is not automatic and authorizes only its explicit continuation call outside the exhausted automatic budget; it does not reset/refill that budget. Unexpected typed/untyped terminal errors are not automatically retried, without removing existing user-directed recovery options.

Every outbound call counts as one attempt, including a call that fails; local mode conversion does not. `[agent] max_retries=4` means four additional retries (five total outbound attempts), default `retry_delay=2.0s` with 2/4/8/16-second exponential delays; zero means initial attempt only. Preserve existing typed transient/permanent classification. An initially selected JSON path retries JSON on recognized transient errors under the same budget. If native calling is locally unsupported (`NotImplementedError` before network I/O), select JSON for the same pinned model; this consumes no attempt, and JSON calls use the shared budget. A recognized transient native network error retries the same native form until budget exhaustion; never switch to JSON to hide provider availability failure. Permanent or other recognized terminal errors propagate. An unexpected untyped exception is logged/sanitized and terminates the request; it never triggers JSON fallback or a new budget. A call that emitted partial output or caused a tool effect is not automatically retried. Earlier completed tool turns do not prevent retrying a later failed request; never replay those tools or restart a whole run automatically. Exhaustion terminates the run while the bot remains available.

Extract existing embedding dispatch and cache into an injected narrow `EmbeddingClient` independent of chat model/client. Require explicit `[embeddings]` model/provider; use only its own configured values or matching provider connection inheritance, never active-chat credentials or endpoint. Missing embedding configuration keeps the bot operational with degraded-index behavior; graph alone is disabled with an actionable warning. Graph enablement and backfill share one prerequisite helper that resolves the explicit canonical `graph_memory.extraction_model` and the valid explicit global embedding model/provider (see the next section). Missing or invalid prerequisites warn actionably and disable graph only; never infer from the main or first catalog item.

### Independent graph resolution

**`ModelRegistry.resolve_graph_model(selector: str) -> RunModel` (PROPOSED, not an existing API).** It resolves the explicitly configured canonical selector exactly (verbatim, no trimming or aliasing; a stale discovered entry is resolvable) independently of the main selection: it works when Main is unselected, missing, or switching, and it never mutates main selection, settings, or revisions. It is a separate entry from `admit`, so ordinary admission keeps its active-Main gate and nothing in the tool, prompt, Telegram, spawn, or scheduler paths can reach it; the composition root hands the resulting pin only to graph code. It follows the same snapshot/credential/recheck shape as `admit`: capture the model record, provider connection fingerprint, and configuration generation under the lock; resolve credentials outside it; recheck those same values; fail typed with no relookup or retry. This recheck happens only inside `resolve_graph_model`, once per resolution, never per extraction. It does not check or capture Main selection, selection revision, or document identity, so an unrelated Main change never fails graph. The returned `RunModel` carries the current catalog and selection revisions read-only for provenance; they gate nothing.

**One pin per component or invocation.** `main.py` resolves one pin when graph memory starts; backfill resolves one pin per invocation. The pin is fixed for that component lifetime or invocation. The extractor closure captures it and, for each extraction call, builds a new owned `LLMClient.for_graph_extraction(pin, ...)` (already present in `llm_client.py:260`) from that same settled pin and closes it in `finally` — the same per-call ownership shape as today's `_llm_call` (`graph_memory.py:1589–1594`), not a component-long shared client. No fingerprint/generation recheck is repeated per extraction. A provider rejection (including a credential that was rotated or removed after the pin) flows through the existing graph failure handling: no re-resolution, no fallback model, and the old pin stays immutable. A rotated or removed credential or a removed catalog entry affects only a later component start or backfill invocation, which resolves anew. Unrelated Main selection changes never invalidate the graph pin or resolver.

**Prerequisites and ordering.** Daemon startup resolves the graph model from the registry only after the normal startup refresh of all providers has completed: providers that refreshed successfully are fresh, providers that failed keep their last-good entries as stale (still resolvable), and no Main selection is required. Startup then resolves the selector, pins it, resolves credentials, checks the explicit embedding model/provider, and runs the budget check before any graph database setup (`GraphMemoryStore`). The budget check is `compute_request_budget` with `input_tokens=0`, `local_context_tokens=agent.ctx_max_tokens`, and `fixed_output_cap=1024`; each extraction then repeats it with the actual estimated input before inference and before usage accounting. Per the preserved budget semantics: unknown `O` is allowed with the fixed 1024 cap; unknown `C`/`T` uses the labelled local fallback; a known `O` below 1024, a malformed limit, or a non-positive headroom fails. Any prerequisite failure produces an actionable WARN and disables graph only. A per-extraction `input_exceeds_budget` fails that extraction through existing graph failure resilience: no lowered cap, truncation, rerouting, or bot abort. If limits are unknown and the provider later rejects the fixed request, existing resilience applies with no second model. Graph's fixed `temperature=0.1` and `max_tokens=1024` stay a named exception; provider adapter compatibility may strip unsupported sampling fields (for example OpenAI reasoning models). Unsupported fixed generation parameters fail through the actual pin/budget validation; the catalog does not infer capabilities from Google resource names or `supportedGenerationMethods`, which remain discovery-only.

**Writer and shutdown.** `GraphMemoryWriter._process_batch` performs extraction synchronously before embedding and graph writes. Successful shutdown requires buffered work to be flushed and the writer to have terminated before the store or any dependency still usable by that writer is closed. `stop(join_timeout=...)` preserves the supplied finite join timeout as a waiting limit. If the worker remains alive after that wait, stopping fails explicitly; it does not return as a successful stop or switch to an indefinite wait. The production shutdown owner reports that failure, does not close the store or dependencies still usable by the worker, and does not claim successful shutdown. Catching a stop failure and continuing dependent teardown is forbidden. There is no component-held extraction client to close: each extraction retains its owned client and closes it in `finally`. Independent explicit global `[embeddings]` remain unchanged.

**Live backfill and dry run.** Standalone live backfill uses the saved catalog only (user-settled): it constructs a read-only registry from configuration and the persisted managed catalog, with no discovery refresh, no network discovery, and no managed-settings write. A missing or corrupt managed catalog or an unresolvable graph model fails with an actionable error (including `/models` refresh instructions) before any database is constructed. It validates the selector, pin, credentials, embeddings, and budget before constructing any database or writing any state, with no side effect on failure; its owned extraction clients are closed in `finally`. The graph pin stays independent of Main, and Main is not modified. Dry run keeps its fast path: it creates no pin, resolves no credentials, builds no clients, and performs no database, embedding, or inference work (it may read input and state only). The legacy helper `build_extraction_llm_call` (`graph_memory.py:1538–1596`) still uses raw `[[models]]` config, falls back to `agent.default_model` and `all_models[0]`, and builds a new `LLMClient` per call; it is not a pinned factory and must be migrated to the pin-capturing closure above, removing that default/first-model inference.

**Implementation boundaries and cutover.** Component preparation precedes production integration. The existing `LLMClient.for_graph_extraction` boundary is verified with a supplied settled pin; shared prerequisite validation and saved-catalog preparation are implemented without changing the legacy extraction-helper contract or its callers. Such injected component coverage proves neither the production extractor closure nor root readiness. The existing `build_extraction_llm_call` is then replaced in one coordinated integration step together with both production caller paths and its three legacy regression tests, once their pin sources are available. No raw-configuration compatibility shim, alternate extraction factory, Main fallback, or per-extraction resolution is introduced. Writer timeout signaling and the production shutdown owner's dependent-resource guard are likewise changed together. All deferred integration and shutdown obligations retain explicit unchecked task owners and remain prerequisites of final completion.

## Risks / Trade-offs

- [Provider metadata can be incomplete, stale, or list models unavailable to this account] -> show source/freshness/unknown state; never promise callability or silently select/fallback.
- [Token estimators and image accounting are approximate] -> label assumed budgets/reserves; enforce known hard caps and fail safely on required unknown outputs.
- [Concurrent refresh, selection, or operator config edits can lose updates] -> one registry write lock, connection fingerprints/generations, atomic settings writes, and stopped-process/lock requirement for migration.
- [Credentials/endpoints could leak through snapshots or errors] -> keep secrets runtime-only, `repr=False`, never persist them, sanitize errors to codes, and retain ADR-0028 private-home restrictions.
- [Provider native/JSON semantics differ] -> one pinned provider per run, same-form retries for typed transient failures, local-only JSON routing for unsupported native calls, terminal unexpected errors, and no replay after effects; preserve tool-turn linearization.
- [PROPOSED scheduler persistence holds `_running_lock` then `_save_lock` across one small-file write and publication] -> prepare and validate the candidate and registrations before locking, revalidate inputs and the file hash under the locks, keep the single lock order `_history_lock -> _running_lock -> _save_lock` for every path, and prove no deadlock with concurrency tests against `_run_job`, reload, history, and state save.
- [A registry refresh inside the credential-resolution window fails a scheduled attempt] -> the post-resolution recheck fails with a typed race code, no re-lookup or retry; the existing scheduled failure record and alert apply.
- [A long-lived graph pin outlives credential rotation or catalog change] -> the pin is fixed per component or backfill invocation and is rechecked only inside `resolve_graph_model`; a later rejection uses existing graph failure handling with no re-resolution or fallback, and the next component start or backfill resolves anew.
- [Rewriting the whole parsed document loses comments and layout] -> accepted: only parsed-value equality is promised (NaN-aware, type-strict); the candidate is roundtripped before commit, the write is atomic with a backup, and load never rewrites.
- [Scheduler-local TOML encoder is wrong for some value] -> narrow supported types only, NaN-aware type-strict roundtrip verification before commit, refuse the write on any mismatch.
- [External edits race the scheduler save] -> a mutation compares the file hash with the stored hash (or missing-file sentinel) under the locks and refuses on divergence; refresh it after every successful save and reload, so operator edits are never overwritten and the scheduler's own write is never mistaken for one.
- [A reload racing a mutation or an operator edit] -> a reload compares disk with the hash of the bytes it parsed (not the old stored hash): an operator edit loads, a mutation committed between parse and publish makes the reload fail with last-good state kept and a "reload again" message, and nothing is retried automatically.
- [A failure after `os.replace` cannot restore the old state, and a partial publication could revert the committed file] -> publish document, hash, and view as one unit; if that cannot complete, latch `RELOAD_REQUIRED` (a plain state flag) and refuse mutations until a reload succeeds; the written file stays authoritative; no transaction framework.
- [Legacy `scheduled_jobs.json` jobs are runnable but read-only] -> the file is never deleted, overwritten, or adopted; TOML wins duplicate tags; modify/remove/pause/resume of JSON-only jobs and removal of a TOML job that shadows a legacy tag (checked against the current legacy file, not a cached map; unreadable legacy data also refuses) are refused with the file path and manual instructions, and list/show mark such jobs `legacy, read-only`, so a removed job cannot reappear.
- [Invalid `overlap_policy` could cancel or restart a running job] -> conservative skip while active, never cancel; otherwise a recorded launch failure.
- [Pre-admission selector evidence could leak a secret-bearing or unbounded value] -> one bounded, redacted representation for list/show, WARN, and records; the raw value stays unchanged in the document.
- [Trusted scheduled source widens the model-shape guard exemption] -> the exemption is limited to `SOURCE_SCHEDULED` supervision, covers only the shape guard, and admission still runs in the root factory.
- [Migration may encounter comments, custom TOML layout, or ambiguous identities] -> preview by default, bound edits to known model/provider keys, prove unrelated parsed values unchanged, stop rather than guess, and require backups/recovery verification.

## Test Strategy

Design-level verification plan; nothing here is implemented or claimed green. Tasks 19/44 and the full 4108P/70F/3E/2S suite remain unwaived and are never reported as passing.

- **Selector matrix:** `None`, `""`, whitespace, non-string forms, exact known (fresh and stale), unknown/case/padding variants x valid Main / stale Main / no Main; credential failure never falls back; one `admit`/`admit_scheduled` per run and no re-admit in `AgentRuntime.create`; ordinary admission still requires Main.
- **Admission races:** provider fingerprint/generation change, Main selection change, document object replacement with equal revision, and refresh inside the credential window; typed failure, no re-lookup, no retry.
- **Scheduler document:** parsed-value roundtrip (strings with control characters, bool vs int, floats incl. `inf`/`nan`, datetimes, arrays, inline tables, quoted keys) with no comment/layout claim; casts; bad whole files at startup and reload; sibling jobs unaffected; last-good reload; load never writes.
- **Write protocol:** mutation hash check against the stored hash and the missing-file sentinel; hash refreshed after every save so a second mutation is not a false external edit; **reload of an operator-edited file publishes the new document (disk differs from the old stored hash)**; **a mutation committed between a reload's parse and publish makes that reload fail with last-good state kept and is never stomped**; no automatic retry; write failure (no swallowed `OSError`); precommit failure leaves old state; post-`os.replace` publication failure latches `RELOAD_REQUIRED` (never a new hash with the old document), mutations are then refused until a successful reload clears it; registration prepare failure leaves no disk partial job; concurrency with `_run_job`, reload, history, and state save proves the single lock order and no deadlock; state JSON safe projection.
- **Mutation dispositions:** cold unparseable/unreadable preflight is `refused` with no mutation; hash race or write failure after `_on_attempt` is `executed` failure; validation refusals precede `_on_attempt`.
- **Legacy JSON:** runnable read-only; TOML wins duplicate tags; modify/remove/pause/resume of JSON-only jobs refused with path and manual instructions; removal of a TOML job shadowing a legacy tag refused; shadow modify/pause allowed; unparseable JSON contained with TOML jobs continuing; partial bad job contained with no drops; operator deletion plus reload removes the job; the shadow check reads the current legacy file (operator adds the tag without reload, then the TOML removal is refused; missing legacy file allows removal; unreadable/malformed legacy refuses before `_on_attempt`); list/show and refusals carry the `legacy, read-only` marker and path/manual instructions; the file is never written; `run_now` uses normal admission.
- **Lifecycle:** overlap -> run ID/tracking -> `last_run` -> admission -> terminal record; `notify=False` still alerts on launch failure; cancel before and during admission; invalid `overlap_policy` skips while active (no cancel) and otherwise records a launch failure.
- **Evidence:** pre-admission WARN and records use the same bounded redacted selector representation as list/show; no raw or non-string content.
- **Graph:** pin independent of Main (absent, stale, switching) and unaffected by unrelated Main changes; one pin per component/invocation, with recheck only inside resolution; per-extraction owned clients from the same pin closed in `finally`; provider rejection uses existing graph failure handling with no re-resolution; daemon startup resolves after the normal startup refresh (fresh and stale-last-good resolvable); standalone backfill uses the saved catalog only with no refresh, no network discovery, and no settings write; missing/corrupt catalog or unresolvable model fails before DB; dry run creates no pins/credentials/clients/DB/embedding/inference; the legacy helper no longer infers `default_model`/`all_models[0]`. Verify both completed-drain shutdown and a deterministically blocked worker exceeding `join_timeout`, including the real production shutdown route: explicit failure, no dependent-resource closure while the worker remains alive, and no success claim. Preserve the legacy helper tests' string-return, message-only `chat`, fixed wire policy, configuration nonmutation, close, and delegation assertions when migrating their construction contract.
- **Budget and storage:** `compute_request_budget` error codes (`invalid_limit`, `output_limit_too_small`, `no_input_budget`, `input_exceeds_budget`) and fixed 1024 with unknown `O`; DB/log rows carry only safe codes; ownership boundaries and secret redaction.

## Open Questions

The accepted records `0034` (partial over `0020`), `0035` (over `0009`), and `0036` (over `0007`) already cover metadata, vision, ignored-fallback behavior, retry ownership, and generation overrides/model resolution. The later ADR stage must add new, scoped records (no edit or repeal of any accepted ADR) for exactly the subset those records do not cover:

- **Scheduled pre-admission selector exception:** `0034`/`0036` require strict resolution and no substitution; the amendment lets `admit_scheduled` classify the raw job selector and inherit Main with a bounded WARN before the pin, and ignores per-job `fallback_models` with a runtime WARN. Existing `0034`/`0036` pinning, canonical ordinary gates, and the no-inference cross-model-retry rule are unchanged. The ADR author must decide explicitly during the ADR batch whether a scoped `0020` clause is needed for its blanket scheduled-selector wording, and record that decision (no accepted ADR is edited now); it is not left conditional.
- **Trusted `admit_scheduled`:** a root-owned scheduled admission with a shape-guard exemption derived from `SOURCE_SCHEDULED`; ordinary admission and its Main gate are unchanged.
- **Graph independence:** `resolve_graph_model` pins an explicit graph model without an active Main, against `0034`/`0036` wording that ties model resolution to an active selection.
- **Scheduler file-failure and legacy-read policy:** isolation of scheduler files, the explicit load result, raw-document persistence, and read-only legacy JSON compatibility, which sit outside the accepted model-catalog records.
- **Naming:** the new safe race code is proposed under the working name `selection_changed`; it does not exist yet.

The earlier supersession tasks for `0007`, `0009`, and `0020` are already done by `0034`–`0036`. ADR-0019, ADR-0021, ADR-0022, ADR-0028, and ADR-0033 are unchanged. The legacy-JSON and standalone-backfill sources are settled by the operator and are no longer open.
