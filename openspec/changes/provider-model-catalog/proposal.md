## Why

Model choices and limits are tied to static or operator-maintained entries, making provider inventories stale and selection, context budgeting, and execution defaults unreliable. A provider-backed catalog with explicit persisted selection will make model knowledge consistent while remaining safe when metadata or service access is unavailable.

## What Changes

- Add provider connections `[providers.<provider-id>]` with `type`, `api_key`, `base_url`, and `request_timeout`; `type` selects `openai`, `openrouter`, `anthropic`, `google`, or cloud-only `ollama`. Discover model IDs and reliable capabilities/limits through each provider's supported catalog API. The connection ID and exact upstream model ID (split at the first `/`) identify a model; catalog availability does not promise account callability.
- Add app-owned `$XDG_CONFIG_HOME/<agent>/models-config.toml` for discovered catalogs and remembered main-model ID. Refresh at startup and `/models`; replace inventory only after a successful per-provider refresh, retain and visibly mark last-good stale inventory on failure, and never silently replace a saved ID. If the saved ID is absent from inventory, retain it and gate model work; if no ID is saved, likewise keep daemon/commands running but gate model work until explicit `/models` selection. Persist each deliberate selection and report persistence failure honestly. Offer a simple roughly-20-item listing; handle Telegram callback limits without a general pagination system, and select only discovered entries. Prompt/tool model consumers share this registry to show available and active models plus known/unknown/stale capabilities, never secrets; availability does not promise account callability.
- Resolve explicit run model selections at admission, otherwise snapshot the active main model; pin its model, endpoint, and metadata through that run. There is no automatic model fallback, including for jobs or vision. Obsolete job selectors fail actionably; no job converter is included. Remove startup-frozen `agent.background_model`.
- Use known model context metadata when present; if absent, use `agent.ctx_max_tokens` as a visible **assumed local budget**, not a claim about provider capacity. Omit `temperature`/`top_p` from ordinary chat, native-tool, and JSON requests; omit an output cap when optional. If required, derive it from reliable model-specific output metadata bounded by remaining context; unknown required output limits fail actionably. Unknown vision capability is visible and image requests fail safely; `vision_query` requires an explicitly selected verified vision model. A manual switch to a smaller model stays selected, but an oversized next request fails without truncating history/source; ordinary compaction remains.
- Require explicit valid `graph_memory.extraction_model` and global `[embeddings]` model/provider when graph memory is enabled; otherwise warn actionably and disable graph only, including backfill. Embeddings remain independent of chat selection and chat credentials/endpoints; preserve explicit embedding configuration and matching-provider inheritance, but remove fallback to active-chat credentials. Preserve graph extraction's fixed `temperature=0.1` and `max_tokens=1024` as a named exception to ordinary request parameter rules.
- Set `[agent] max_retries=4` (additional attempts, five total), `retry_delay=2.0s`, exponential delays 2/4/8/16; `max_retries=0` means the initial attempt only. Remove provider/model retry knobs. Retry transient provider failures only; permanent failures stop immediately. Keep one automatic attempt budget across native/JSON, human-wait, and empty-output control-flow paths. Retry a failed current request only before it emitted output or caused a side effect; earlier completed tool turns need not prevent retry of a later failed request. Never replay completed tools or a whole run automatically. Explicit checkpoint recovery remains user-directed, not an automatic retry or implicit budget reset; terminal errors end the run, not the bot.
- **BREAKING:** Replace `[[models]]`/per-model settings with provider connections and discovered catalogs; remove per-model/provider generation and retry tuning, moving retry controls to `[agent]`, and remove per-call generation overrides (including `max_tokens`, `temperature`, and `top_p`). Move main selection from `agent.default_model` to app-owned preferences; remove `agent.background_model`. Remove/reject agent and job fallback settings, vision auto-routing, and local Ollama defaults/selection (local Ollama users must explicitly choose a cloud replacement; do not guess from `:cloud`). Migrate only unambiguous configuration using preview, backup, recovery, and idempotent reruns; preserve unresolved TOML references without expanding secrets, report discarded tuning without promoting it or creating hidden overrides, require operator choice for ambiguous account selectors, and seed the main selection only from an unambiguous old startup default. Do not rewrite jobs, logs, prompts, memories, vectors, or reconstruct manual-switch history.

## Capabilities

### New Capabilities
- `provider-model-catalog`: Provider connections, discovered catalog and metadata, persistence/refresh, explicit selection, admission-time run model resolution/pinning, migration, graph prerequisites, and shared availability reporting.

### Modified Capabilities
- `per-model-context-window`: Use catalog context/output metadata, expose unknown context limits while retaining the assumed local budget, remove vision auto-routing and fallback selectors, and preserve normal compaction.
- `provider-credential-inheritance`: Replace configured model entries; preserve explicit embedding configuration and provider inheritance, but prohibit active-chat credential fallback for embeddings.
- `llm-error-recovery`: Define bounded agent retry defaults while keeping explicit checkpoint recovery distinct and preserving terminal bot behavior.
- `agent-runtime-construction`: Remove per-call generation-tuning overrides and carry the admission-resolved model contract through runtime construction.
- `native-tool-calling`: Use the shared request parameter contract and retry budget across native/JSON requests without resetting the budget or replaying completed tool effects.
- `xdg-path-resolution`: Resolve the app-owned model-catalog file beneath the agent's XDG config directory.
- `telegram-command-surface`: Add `/models` for catalog listing, refresh, and explicit main-model selection.

## Impact

Configuration and provider adapters (`config_schema.py`, `main.py`, `llm_client.py`, `providers/`); catalog persistence and XDG paths (`xdg.py`); request budgeting (`react_loop.py`, `context_manager.py`); graph startup/backfill (`graph_memory.py`, `backfill_graph_memory.py`); run admission (`agent_runtime.py`, `agent_controller.py`, `scheduler.py`); prompt/tool model awareness (`prompt_builder.py`, `prompt_loader.py`, built-in tool schemas/descriptors); Telegram interface, commands, callbacks, and help; migration and config examples. Existing provider API dependencies remain; no dependency is required.
