## Why

The predecessor `provider-model-catalog` change (committed at `a57ab26` on the feature branch) introduced provider-backed discovery, persistent catalog state, and rich runtime budgeting as an execution authority. That authority is heavier than the runtime needs: the operator already benefits from an advisory catalog and a deliberate selection, while the ReAct loop only needs one pinned model, simple context statistics, and a trusted compaction step. This change simplifies the model runtime so discovery is a convenience, configuration is explicit, and the existing loop, scheduler, and security boundaries stay intact.

## What Changes

- **Advisory catalog only.** Discovered provider inventories become a disposable local cache. The cache never whitelists models, gates execution, carries public supplement metadata, or claims per-field provenance. Discovered false or unknown capability metadata does not block image or tool requests to the pinned model; genuine adapter/protocol limitations and provider errors remain. Refresh updates the cache but never invalidates an active selection or a pinned run.
- **Fixed chat connections.** Provider connections are fixed for the process lifetime; changes require a restart. Discovery runs over those immutable connections.
- **Simplified first-run selection.** Startup discovery runs automatically only when both a saved selection and cached candidates are absent. Otherwise the saved selection is used; if no selection is saved, the first candidate in stable canonical-ID order is chosen in memory and is **not** persisted. If discovery yields no candidates, including when every provider fails, commands remain available; implicit model requests report missing selection and valid explicit model requests remain possible.
- **Deliberate selection persistence.** `/models` selections are persisted separately from the catalog cache. Automatic first-model choices stay in memory only; an unsaved selection is re-derived from the cache on the next startup.
- **Immutable run targets.** Explicit selectors and the active main model resolve at admission to a single pinned model/connection snapshot; cached metadata, when available, is informational only. Ordinary explicit requests, like explicit scheduled requests, require a configured target connection but no active main selection or catalog membership. There is no mid-run model switch, no random startup model, no fallback chain, and no capacity-driven repair.
- **Strict scheduled-job model handling.** A missing job `model` selector inherits the active main model. An explicit selector is attempted exactly as supplied. Malformed selectors or provider errors fail only that **Scheduled run**, without substituting another model and without requiring a separate main-model prerequisite. TOML scheduling, job history, ownership, notifications, and safe persistence remain unchanged.
- **Independent embeddings and graph extraction.** Embeddings and graph extraction each have their own provider, endpoint, key reference, and model. Neither inherits from chat selection nor from each other, and graph memory has no catalog dependency. Graph vectors use the same explicitly configured embedding service as other indexing; graph extraction uses its own LLM configuration, with no fourth graph-specific embedding configuration.
- **Context monitoring and compaction reduced to statistics and summarization.** Context-window tracking stays informational. Fit enforcement, reserves, model-switch guards, and automatic overflow repair are removed. One configured, model-independent compaction threshold remains; the existing summarizer keeps task and recent complete turns and publishes a replacement only on successful summary. On automatic compaction failure the loop warns, continues with unchanged history, and disables further automatic compaction for that run. Manual `/compress` keeps original history on failed or empty summarization.
- **Legacy removal scoped to model handling and scheduler configuration.** Automated model-configuration migration, obsolete `[[models]]`/per-model settings, `agent.default_model`, `agent.background_model`, per-model/provider retry or generation tuning, and obsolete scheduler representations are removed. Unsupported values produce actionable errors, not converters, shims, or silent reinterpretation. Unrelated storage-layout migration, historical log/execution-record readers, memory formats, permissions, and cancellation behavior are untouched.
- **Safety and ownership preserved.** Credential routing, secret redaction, per-run targets, message integrity, cancellation/resource ownership, atomic basic writes, retry/checkpoint behavior, runtime cancellation, and persistence security remain unchanged.
- **Test strategy.** Inventory tests as keep/rewrite/retire/add before deletion; move generic regressions out of removed files; retain real client/root tests. The goal is correct coverage, not a test-count reduction.
- **Out of scope.** `/stop` redesign, retry/checkpoint policy changes, XDG data migration, historical log readers, memory format changes, and unrelated security/cancellation work are excluded.
- **Proposed defaults (not yet confirmed).** Numeric output-cap and compaction-threshold defaults remain design choices. A single configured output-cap value is used only where an API requires one.
- **BREAKING:** The catalog is no longer an authority, request budgeting/fit enforcement and automatic overflow repair are removed, per-model/provider generation/retry configuration is rejected, legacy model/scheduler migration is removed, and old configuration values no longer convert automatically.

## Capabilities

### New Capabilities

- `provider-model-catalog` (pending predecessor capability, not yet canonical on `main`; source baseline: predecessor `provider-model-catalog` at `a57ab26`): provider connections, advisory discovered catalog, explicit selection persistence, admission-time run pinning, and independent embeddings/extraction configuration. This change supersedes the predecessor's authority contracts—catalog whitelisting/gating, request budgeting/fit enforcement, public metadata supplementation, automated migration, and legacy compatibility—before the capability becomes canonical.

### Modified Capabilities

- `agent-runtime-construction`: Remove per-call `max_tokens`, `temperature`, and `top_p` overrides; carry an admission-resolved immutable model snapshot through runtime construction. Profiles, product surface, context assembly, supervision, and scheduling semantics are unchanged.
- `provider-credential-inheritance`: Chat models use their owning chat connection's credentials and transport. Embeddings and graph extraction instead require independently configured provider, endpoint, key reference, and model: neither may inherit from chat connections, even a matching provider, or from each other. Graph vectors share the explicit embeddings service; graph extraction retains its own LLM configuration. Supersede the predecessor's matching-chat-provider embedding inheritance.
- `per-model-context-window`: Reduce to informational token statistics and one configured, model-independent compaction threshold. Remove hard fit enforcement, reserves, model-switch guards, automatic overflow repair, and vision auto-routing. Compaction replaces history only on successful summary; failed/empty summarization preserves the original history.
- `context-monitoring`: Replace canonical completion-reserve, capacity/headroom, and capacity-percentage contracts with informational token counts and the configured compaction threshold; no inferred model capacity or budgeting display.
- `native-tool-calling`: Replace the predecessor's pending actual-wire budget-enforcement requirements with informational accounting and threshold-based compaction. Preserve native dispatch, payload/schema integrity, message pairing, real adapter limitations, and existing retry/checkpoint policy.
- `telegram-command-surface`: Add `/models` as the catalog listing, refresh, and selection command; keep `/compress` as a hidden advanced command. Existing public, hidden, and help contracts are otherwise unchanged.
- `scheduled-job-execution`: Simplify model selector handling: an absent selector inherits the active main model, an explicit selector is used exactly, malformed selectors or provider errors fail only that job, and no fallback or extra main-model prerequisite is introduced. TOML scheduling, **Job-owned context**, history, notifications, and persistence remain unchanged.
- `xdg-path-resolution`: Resolve durable deliberate-selection preferences separately from disposable catalog-cache persistence through the central XDG resolver. Replace the predecessor's combined managed selection/catalog document; exact filenames and storage locations remain design work.

## Impact

Affects provider connection parsing and chat client construction (`config_schema.py`, `llm_client.py`, `providers/`), catalog/selection persistence (`xdg.py`, model settings file), run admission and runtime construction (`agent_runtime.py`, `agent_controller.py`, `sub_agent_supervisor.py`), request preparation/context management (`react_loop.py`, `context_manager.py`, `context_monitor.py`), embeddings and graph startup/backfill (`graph_memory.py`, `backfill_graph_memory.py`), scheduler job execution (`scheduler.py`, `builtin_tools/schedule.py`), Telegram commands/callbacks/help (`telegram_commands.py`, `telegram_callbacks.py`, `telegram_interface.py`), and the removal of migration tooling and legacy configuration handling. Existing provider API dependencies remain; no new external dependency is required.

This proposal is planning-only. It depends on the predecessor `provider-model-catalog` implementation at `a57ab26` and its pending (not yet canonical) specifications. Durable architectural decisions that supersede predecessor ADRs will be captured as new scoped ADRs in the later ADR stage. The agreed route publishes only reviewed planning through a planning-only branch based on `main`; the exact planning state must be committed and merged to `main`, then brought back to the implementation branch, before apply. Implementation merge is not part of this batch.
